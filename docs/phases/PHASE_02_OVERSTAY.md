# Ф2. Перестой: машина стоит после даты выезда

Статус: **архитектура v1 (22.09.2026), ответы пользователя получены (§11), ждёт независимой критики.** Кода нет.

Порядок фазы (`docs/TZ_2026-09-21_PLAN.md` §5а): архитектура → критика → код → тесты → ревью → stage.

## 1. Зачем

ТЗ 1.1 требует учитывать при подтверждении «автомобили, которые уже находятся на парковке». Решение пользователя 22.09 (PLAN §1): если машина стоит дольше даты выезда, **место считается занятым**, администратору **сразу** уходит уведомление (разобраться, выяснить причину, освободить место), а пока ситуация не решена, **стоимость продолжает начисляться и подсвечивается отдельно как ДОЛГ**.

Сейчас всё наоборот:
- бронь «Заехал» с прошедшей датой выезда выпадает из всех подсчётов занятости (`occupancy.ts:28,70,103,127`, `autoconfirm.ts:33` — везде `dateTo >= from`). Автоподтверждение может отдать физически занятое место, «Свободно сейчас» завышено;
- долг за лишние сутки нигде не считается. Табло «Сегодня» и экран охраны только помечают «просрочен выезд»;
- при выезде пересчёт по факту (`actualDays`) считает сутки от фактического заезда. Кто приехал на 2 дня позже и уехал на 1 день позже, получает `actualDays = days`, и `transition` сам ставит «решено» (`bookings.ts:116`) — перестой теряется. Кто приехал вовремя и задержался, получает баннер с полным пересчётом по тарифу (`quote(actualDays)`), где длинная бронь может перейти на тариф 250 ₽ и выйти *дешевле*;
- уведомления о перестое нет. У `AdminNotice` нет ключа дедупликации, колокольчик не обновляется без перезагрузки страницы.

На stage сейчас 3 брони в перестое (демо-данные): №4 — выезд 27.08, №6 — 31.08, №1 — 03.09.

## 2. Что входит и что нет. Деление на две части

Фаза большая: в ней и деньги, и занятость, и первый скан планировщика. По правилу «лучше больше фаз, но каждая проработана» делим на две части. Каждая часть проходит код → тесты → два раунда ревью → stage отдельно. Архитектура и критика общие.

**Ф2а. Занятость и ДОЛГ** (схема базы не меняется):
- машина в перестое занимает место, пока ситуация не решена — одно правило для всех подсчётов;
- чистый модуль расчёта перестоя и долга (`src/lib/overstay.ts`);
- показ перестоя и ДОЛГА: карточка брони, доска и таблица, «Сегодня», экран охраны, карточка клиента, дашборд владельца;
- при выезде долг начисляется в сумму брони (§4.3), запись в ленте.

**Ф2б. Уведомление** (две добавляющие миграции):
- первый скан планировщика `overstay`: уведомление администратору один раз на перестой, запись в ленте брони, само закрытие уведомления, когда перестой решён;
- новый вид уведомления `OVERSTAY`, ключ дедупликации в `AdminNotice`;
- переключатель режимов сканов «выкл / пробно / вкл» в карточке «Планировщик» (обещан в Ф1 на Ф2);
- починка колокольчика из ревью этапа 1: «Прочитано» только для показанных, проверка роли, опрос раз в минуту вместо застывшего бейджа.

**Не входит:** сообщение клиенту о перестое (в ТЗ нет); уведомление администратору в мессенджер (Ф4, через Outbox и `admin.notifyPhone`); кнопка «принять долг» одним действием (продление + оплата) — вместе с кассой (Ф11); возврат при досрочном выезде и расхождение баннера пересчёта с действием (Ф10, см. §12); перестой в комнатах; панель занятости по ТЗ (Ф3).

## 3. Определения

| Понятие | Определение |
|---|---|
| Перестой | Бронь парковки в статусе «Заехал», у которой **сегодня по Москве позже даты выезда**. День выезда оплачен (сутки считаются по датам включительно), поэтому первый день перестоя — следующий за датой выезда. *Ответ 1.* |
| Сутки перестоя | `сегодня − дата выезда` в календарных днях по Москве. Выезд 25.09, сегодня 27.09 → 2 сут. |
| Цена суток | **Текущий тариф по типу машины** (ответ пользователя, вопрос 2 — б): то же правило выбора, что в `quote` — тариф типа ТС с наибольшим `minDays`, не превышающим сутки брони. Легковая 350 ₽, от 30 суток — 250 ₽; кроссовер 400 ₽; мото 150 ₽. Скидка и ручная цена брони на долг не влияют. Фура «по запросу» (тариф 0) → цена суток 0, показываем «стоимость не задана». Сутки брони — плановые (`days`), не плановые + перестой: бронь на 29 суток, задержавшаяся на 3, считается по 350 ₽ |
| ДОЛГ | `сутки перестоя × цена суток`. Не хранится — считается на лету, поэтому «начисляется» сам каждые сутки. Показывается **отдельно** от обычного «не оплачено». |
| Решено | Бронь вышла из «Заехал» (выехал; исправление статуса) или дата выезда перенесена на сегодня и позже (продление через «Изменить»). |

## 4. Решения

### 4.1 Занятость (Ф2а)

1. **Одно правило в одном месте.** Чистая функция `effectiveSpan(b, today)` в `src/lib/occupancy-math.ts`: для «Заехал» с `dateTo < today` конец отрезка — `OPEN_END = "9999-12-31"`. Остальные брони без изменений.
2. **«Пока не решено» значит и в будущие дни.** Машина в перестое занимает место на все дни вперёд, в том числе при решении об автоподтверждении на следующую неделю и в сетке на 3 недели. Когда машина уедет — неизвестно, а лишняя свободная клетка опаснее лишней занятой. Забытый «Выехал» будет держать место — это и лечит уведомление.
3. **Выборка — надмножество, отрезок — через `effectiveSpan`.** Фрагмент условия `occupiesWhere(from, to)`: активные статусы, `dateFrom <= to` и (`dateTo >= from` **или** статус «Заехал»). «Заехал» со старой датой выезда, но ещё не в перестое на дату запроса, отсеивается уже в памяти. Число «Заехал» ограничено вместимостью (~415), выборка дешёвая.
4. **Где применяется** (все места, найденные ревью этапа 1):
   - `poolSpans` (`occupancy.ts:64`) и `poolPeak` (`autoconfirm.ts:26`) — объединяются в одну функцию `poolSpans(db, pool, from, to, today)` в `occupancy.ts`, `db` — транзакция автоподтверждения или `prisma`;
   - `occupancy()` по категориям (`occupancy.ts:21`, только парковка) — ей пользуются сетка и подсказка «свободно» в CRM до Ф3;
   - `parkingDashboard.held` (`occupancy.ts:103`) и `occupancyToday` (`occupancy.ts:127`) — это подсчёт на один день, там достаточно условия `occupiesWhere`.
5. **`today` — снаружи.** Страницы передают `todayIso()`, автоподтверждение — `moscowIso(new Date())`. Для этого `todayIso` разделяется на `moscowIso(d: Date)` и обёртку (формат в `actualParkingDays` уже такой же — туда тоже `moscowIso`).
6. Брони «Ожидает оплаты» и «Подтверждена» с прошедшей датой выезда место **не** держат, как и сейчас: машины на парковке нет. Их закрывает автопереход «Не приехал» (Ф7).

### 4.2 ДОЛГ — расчёт (Ф2а)

7. **Чистый модуль `src/lib/overstay.ts`** без базы и без `server-only` (его используют и серверные страницы, и тесты):
   - `overstayDays(b: { kind, status, dateTo }, today)` → число, 0 — не перестой;
   - `pickTariff(tariffs, vehicleType, days)` — выбор тарифа, общий с `quote` (`pricing.ts` переходит на него, правило одно);
   - `dayRate(tariffs, b)` → цена тарифа для `b.vehicleType` и `b.days`, 0 — тариф не найден или «по запросу»;
   - `overstayDebt(b, today, tariffs)` → `{ days, rate, debt } | null`;
   - `checkoutCharge(b: { kind, vehicleType, dateTo, days, amount }, outDate, tariffs)` → `{ extra, rate, days, amount } | null` — то же правило для момента выезда.
8. **Считается на сервере, в клиентские компоненты уходит готовое** `{ days, debt }` (правило «признак считается на сервере», иначе гидратация на границе суток расходится). Страница читает активные тарифы парковки один раз (таблица из 5 строк) и считает долг для всех строк.
9. Долг не хранится и не пишется сканом каждые сутки: запись раз в сутки дала бы второй источник правды и потребовала бы сверки. Материализуется один раз — при выезде.

### 4.3 Выезд — начисление (Ф2а)

10. **При «Выехал» долг сразу добавляется в сумму брони**, если дата выезда по Москве позже плановой: `сутки += extra`, `сумма += extra × цена суток`. В ленте: «Начислен перестой: 2 сут. × 350 ₽ = 700 ₽ · 3 → 5 сут., 1 050 → 1 750 ₽», автор — кто нажал «Выехал», в журнале аудита то же. После этого долг виден как обычное «не хватает 700 ₽» — на доске, в карточке, у клиента, и «Принять оплату» подставляет сумму. *Ответ 3.*
11. **Снять долг — через существующее «Изменить цену», причина обязательна** (например, «охрана забыла отметить выезд 25.09»). Отдельной кнопки не делаем.
12. **Правило перестоя важнее пересчёта по фактическим суткам.** Если начислен перестой, `recalcDecidedAt` ставится сразу, и баннер «Стоянка по факту» не появляется. Пример: бронь 20–25.09 (6 сут.), приехал 22-го, уехал 26-го — по факту 5 сут., но место держали с 20-го, поэтому начисляется +1 сут., а не возврат. Досрочный выезд без перестоя идёт по-старому (баннер), его переделывает Ф10.
13. **Та же ошибка, что сейчас (`bookings.ts:116`), закрывается:** «решено» ставится автоматически, только если нет ни перестоя, ни расхождения суток.
14. `correctStatus` («Исправить статус») долг **не** начисляет: автоматизации там по правилу не запускаются.
15. Начисление внутри транзакции `transition`, одним `update` с остальными полями выезда. Тарифы читаются в той же транзакции; сутки для выбора тарифа — плановые, *до* начисления.
16. **Фура «по запросу» (тариф 0):** при выезде сутки увеличиваются, сумма нет; в ленте «Перестой 2 сут.: тариф не задан — уточните сумму» (дальше «Изменить цену»).

### 4.4 Показ (Ф2а)

| Где | Что |
|---|---|
| Карточка брони | Красная плашка под полосой этапов: «ПЕРЕСТОЙ · 2 сут. · ДОЛГ 700 ₽ — выезд был 25 сент. Место занято, пока машина на парковке. Выясните причину: продлите бронь («Изменить» → дата выезда) или отметьте выезд». В блоке «Оплата» — отдельная красная строка «ДОЛГ за перестой 700 ₽», не смешанная с «не хватает» |
| Доска и таблица | Красный значок «перестой 2 д · 700 ₽» на карточке в колонке «Заехал» и в строке таблицы |
| «Сегодня» | В «Отправлении» вместо «просрочен выезд» — «перестой 2 сут. · долг 700 ₽» красным |
| Экран охраны | Во вкладке «Выезд» — «ПЕРЕСТОЙ 2 СУТ. · ДОЛГ 700 ₽» красным; кнопку «Выехал» не блокируем. *Ответ 5* |
| Карточка клиента | В списке броней — «перестой · долг 700 ₽» отдельно от обычного долга |
| Дашборд владельца | Плитка «Перестой: 3 машины · долг 17 500 ₽» |

Фура «по запросу»: «перестой 2 сут. · стоимость не задана».

### 4.5 Уведомление — скан `overstay` (Ф2б)

17. **По контракту скана** (`docs/phases/PHASE_01_SCHEDULER.md` §5): `run(tx, now)`, идемпотентный и догоняющий, только запись в базу, лимит 50 новых за вызов, выкатка «выкл → пробно → вкл». Блокировка занятости не нужна — скан занятость не меняет.
18. **Ключ дедупликации** `overstay:<id брони>:<дата выезда>`. Один перестой — одно уведомление. Если бронь продлили, а машина снова задержалась, это новый перестой с новым ключом. *Ответ 4.*
19. **Ход скана:**
    1. `today = moscowIso(now)`;
    2. все «Заехал» парковки с `dateTo < today` (десятки строк) → ключи;
    3. какие ключи уже есть в `AdminNotice` → чистая функция `planOverstay(rows, existing, limit)` отдаёт новые, старые по дате выезда первыми;
    4. `adminNotice.createManyAndReturn({ skipDuplicates: true })` — вставка без ошибки уникальности (ошибка переводит транзакцию в «aborted»); для каждой вставленной — запись в ленту брони, `type SYSTEM`, `userId = null`: «Перестой с 26 сент.: машина на парковке после даты выезда. Уведомлён администратор»;
    5. **само закрытие**: непрочитанные `OVERSTAY`, чей ключ не входит в текущие перестои (выехал, продлили), помечаются прочитанными с `readById = null` — колокольчик не напоминает о решённом. Запрос дешёвый, лимит не нужен;
    6. возвращает число новых уведомлений.
20. **Текст:** «Перестой: бронь №12, А123ВС777 — выезд был 25 сент., машина на парковке. Выясните причину и освободите место».
21. На stage после включения три демо-брони получат уведомления — это ожидаемо, число видно заранее в режиме «пробно».

### 4.6 Колокольчик (Ф2б) — находки ревью этапа 1

22. «Прочитано» гасит **только показанные** уведомления: `markNoticesReadAction(ids)`, `ids` обязателен (`REVIEW_2026-09-22_STAGE1.md` — три находки про `notices.ts:25`).
23. Действие — только `OWNER` и `ADMIN` (`requireActor(STAFF)`), сейчас без роли (находка `settings.ts:47`).
24. **Бейдж не застывает:** начальный список по-прежнему из `AdminShell`, дальше `NoticeBell` раз в 60 с опрашивает `GET /api/admin/notices` (сессия, `OWNER`/`ADMIN`; `/api/admin` уже закрыт в `proxy.ts` по cookie) и при открытии панели. Layout в Next 16 при переходах не перерисовывается (находка `AdminShell.tsx:9`), а уведомление о перестое приходит ночью само, без действия администратора.
25. `revalidatePath("/admin", "layout")` заменяется на путь с группой `"/admin/(app)"` или убирается совсем — после опроса он не нужен (находка про `revalidatePath`). Решение — на коде, по `node_modules/next/dist/docs/`.

### 4.7 Режимы сканов в карточке «Планировщик» (Ф2б)

26. В реестре скана появляется подпись: `{ code: "overstay", label: "Перестой", run }`. Список кодов и подписей — в чистом модуле, чтобы карточка не тянула Prisma планировщика.
27. В карточке — строка на скан: переключатель «Выкл / Пробно / Вкл» и итог последнего тика из пульса («пробно: 3», «вкл: 0»). Только владелец, `setScanModeAction(code, mode)` пишет `Setting "scheduler.scans"` целиком и запись в журнал аудита. Неизвестные коды и режимы отклоняются.

## 7. Критерии приёмки

**Ф2а**
1. Бронь «Заехал» с выездом вчера: +1 к «Занято сейчас», к полосе «Сегодня», к пулу сегодня и в каждый следующий день сетки; автоподтверждение на даты через неделю её учитывает.
2. «Заехал» с выездом сегодня — не перестой (день выезда оплачен); «Подтверждена» с выездом вчера — место не держит.
3. Граница суток по Москве: 21:00 UTC — уже следующий день.
4. Карточка, доска, таблица, «Сегодня», охрана, клиент, дашборд показывают одни и те же сутки и сумму.
5. «Выехал» при перестое: сумма и сутки увеличены, запись в ленте, баннера «по факту» нет, «не хватает» = долг. Без перестоя всё как раньше.
6. Поздний заезд + перестой: начисляется перестой, не возврат.
7. «Исправить статус» в «Выехал» долг не начисляет.

**Ф2б**
8. «Пробно»: в пульсе `dry.overstay = N`, уведомлений нет. «Вкл»: N уведомлений и N записей в ленте; повторный тик — 0 новых.
9. Продлили бронь или отметили выезд → следующий тик закрывает уведомление, колокольчик его не показывает.
10. Продлили, и машина снова задержалась → новое уведомление.
11. Бейдж обновляется без перезагрузки в течение минуты; «Прочитано» не гасит пришедшие после открытия панели; охрана действие вызвать не может.
12. Режимы меняет только владелец, изменение в журнале.

## 8. Тесты

**Юнит (без базы):**
- `effectiveSpan` / `loadByDay`: перестой занимает сегодня и будущие дни; «Заехал» с будущим выездом — по плану; «Подтверждена» с прошедшим выездом не продлевается; запрос на даты позже старого выезда не в перестое ещё не считает бронь.
- `overstayDays`: выезд сегодня → 0, вчера → 1, не «Заехал» → 0, комната → 0.
- `moscowIso`: 20:59 UTC и 21:00 UTC по разные стороны суток.
- `pickTariff` / `dayRate`: легковая 3 сут. → 350, 30 сут. → 250, 29 сут. → 350; кроссовер → 400; мото → 150; фура → 0; тип без тарифа → 0; скидка в сумме брони на цену не влияет; `quote` после перехода на `pickTariff` даёт прежние суммы.
- `checkoutCharge`: выезд в плановый день → нет; на день позже → +1 сут. и цена тарифа; поздний заезд + перестой; фура → сутки растут, сумма нет; бронь со скидкой → долг по тарифу.
- Ф2б: `overstayKey`, `planOverstay` (новые, уже известные, лимит, порядок), список ключей для закрытия.

**E2E `tests/e2e/overstay.mjs`** (вход владельцем, запускается и против stage):

## 9. Риски

| Риск | Что делаем |
|---|---|
| Забытый «Выехал» держит место на все будущие дни и снижает автоподтверждение | Так и задумано («пока не решено»); уведомление и плашки заставляют решить; на stage автоподтверждение выключено |
| Ложный долг, если охрана отметила выезд на дни позже | Снимается «Изменить цену» с причиной; запись в ленте показывает, откуда сумма |
| Разные экраны считают долг по-разному | Одна чистая функция, в компоненты — готовые числа |
| Владелец поменял тариф — долг текущих перестоев пересчитался | Так и решено: «по текущему тарифу». В ленте при выезде записываются сутки и цена, по которой начислено |
| Граница суток на сервере в UTC | `moscowIso` везде, тест на 21:00 UTC |
| Изменение правила выезда ломает пересчёт по факту | Ветка без перестоя не меняется; e2e `crm-pipeline` прогоняется как есть |
| Скан на stage создаст уведомления о демо-бронях | Ожидаемо, число видно в режиме «пробно» до включения |
| Опрос колокольчика нагружает сервер | Раз в 60 с, один лёгкий запрос, только на открытой вкладке CRM |

## 10. Выкатка

Для каждой части: локально юнит + e2e (включая старые сценарии) + `npm run build` → независимое ревью → правки → подтверждающее → бэкап на stage → выкатка по HANDOFF §3 → e2e против stage → `cleanup.sql` → `DEPLOYED_COMMIT` → HANDOFF и таблица фаз.

Ф2б на stage: скан выкатывается «выкл» → «пробно» (ожидаем 3 — демо-брони) → «вкл» после e2e.

## 11. Ответы пользователя (22.09)

| Вопрос | Ответ |
|---|---|
| 1. С какого момента перестой | **С 00:00 по Москве следующего дня после даты выезда** — день выезда оплачен |
| 2. Цена суток долга | **Текущий тариф по типу машины** (350 / 400 / 150, легковая от 30 суток — 250). Скидка брони не влияет; у фуры «по запросу» долг не считается — «стоимость не задана» |

| 4. Уведомление | **Один раз**, когда перестой начался; дальше бронь подсвечена везде, пока не решено |
| 5. Охрана | **Видит «ПЕРЕСТОЙ · ДОЛГ», выпускает**, долг принимает администратор; кнопку «Выехал» не блокируем |

Решено без вопросов (пользователь не возразил): перестой держит место и на будущие дни; «решено» = выехал или продлили дату; при позднем заезде с перестоем начисляется перестой, а не возврат; долг показывается на шести экранах из §4.4; перестой в комнатах не считаем.
