4. Риски:
- Баннер «по факту» и само действие считают по-разному: цена одних суток против quote(actualDays). Для броней от 30 суток баннер может показать «Доплату», а действие даст «Переплату».
- Пересчёт идёт по тарифу и теряет ручную цену (поле Booking.discount в src не используется), поэтому возврат получается завышенным.
- Сторно ошибочной оплаты нет. Ошибку гасят обычным возвратом, и после Ф11/Ф12 он попадёт в кассу и отчёт как настоящий возврат денег: решить в Ф10/Ф11.
- «Исправить статус» даёт администратору открыть закрытую бронь и обойти правило «деньги после выезда — владелец» (бэклог Ф10).
- Бэкапов по крону нет (МФ-3а), их нужно сделать до Ф11: касса — это деньги.
- Дашборд считает месяц по UTC (с 03:00 МСК 1-го числа), а отчёт Ф12 будет считать по Москве. Без общего помощника цифры разойдутся.
- В журнале аудита CREATE Payment пишет id брони, а не id платежа (bookings.ts:325). Для «истории для проверки» кассы (7.4) лучше писать id платежа — мелочь, в фазы не записана.
