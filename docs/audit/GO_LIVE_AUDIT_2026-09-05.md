## 3. Находки по приоритетам

**P0 — без этого в бой нельзя**
1. **Бэкапы БД**: cron `pg_dump` ежедневно в `/opt/parking24/backups` + копия за пределы сервера + проверенное восстановление. (0.5 дня)
2. **Планировщик Outbox + хотя бы один реальный канал отправки** (WhatsApp через провайдера или, минимум, Telegram-бот). Без него подтверждения/напоминания клиенту — фикция. (1–2 дня + аккаунт провайдера от заказчика)
3. **Сид демо-данных**: `demo()` только при `SEED_DEMO=1`, на бою выключить. (0.2 дня)
4. **Экраны настроек M4**: пользователи + смена пароля, тарифы, ёмкость, политика отмены, шаблоны, правила. Сейчас 6 ссылок в 404, а без ёмкости от заказчика «занятость» показывает плейсхолдер 60/30/10/5. (2–3 дня)
5. **Боевой домен + robots/sitemap + перенос**: решение заказчика по домену (parking24pitstop.ru?), DNS, сертификат, `robots` allow, `NEXT_PUBLIC_SITE_URL`. (0.5 дня после решения)
6. **Юрисдикция хостинга (152-ФЗ)**: VPS2 — не РФ. Либо боевой сервер в РФ, либо письменное решение заказчика. Плюс политика и оферта — на проверку юристу. (решение заказчика)
7. **Вернуть боевой WhatsApp 79055250660** в `src/lib/tariffs.ts`. (5 минут, в день запуска)

**P1 — до приёмки заказчиком**
1. Блокировка перебора паролей (5 ошибок → 15 минут по логину+IP), лог неудачных входов.
2. Единая таймзона Europe/Moscow: карточка брони показывает время браузера (16:55), карточка клиента — UTC (09:55), правильно 12:55. Все `toLocaleString` → `fmtDateTime`.
3. Канбан на ноутбуке 1440 px: 6 колонок = 1692 px, «Заехал/Выехал» за краем, перетащить туда без автоскролла нельзя. Сделать колонки 232 px, «Выехал» и «Отменена» сворачиваемыми.
4. Экспорт CSV: сейчас доступен админу и не пишется в журнал; по ТЗ — только владелец + запись `EXPORT` в AuditLog.
5. Заголовки безопасности в nginx (HSTS, X-Frame-Options DENY для /admin, nosniff, Referrer-Policy), убрать `x-powered-by`.
6. ufw (22/80/443), SSH только по ключу, отдельный пользователь вместо root.
7. Лид с /rooms в CRM (доска «Комнаты») — сейчас теряется, нарушает цель №1 ТЗ «ни один клиент не теряется».
8. Отдельные страницы /tariffs, /faq, /contacts, /about + canonical/OG/JSON-LD/sitemap — иначе SEO-часть §5 не выполнена.
9. Дашборд владельца до §11: конверсия заявка→оплата по источникам, средний чек, доля повторных, загрузка по дням, сумма возвратов.
10. 2FA для владельца/админа (§8.4) — хотя бы TOTP, поле `totpSecret` уже в схеме.
11. Предупреждение при «Заехал» раньше даты заезда и при овербукинге по ёмкости (сейчас бронь на 6–9 сентября заехала 5-го молча).
12. Экран охраны: на клавиатуре только буква «А» — поиск по буквам номера невозможен (только цифры, телефон, № брони). Добавить полный ряд букв госномера (А В Е К М Н О Р С Т У Х).
13. Мониторинг: uptime-пинг https + алерт в Telegram при падении контейнера; ротация логов docker.

**P2 — после запуска**
- Визард /booking + ЮKassa + автоворзвраты (§6) — крупный модуль, стартовать только после ответов №1–3 заказчика.
- PWA-манифест и офлайн-очередь охраны (M3).
- Шифрование телефонов/госномеров в БД (§12), тач-таргеты и alt на сайте, `cache-control` главной при тарифах из БД (сейчас s-maxage=1 год для статики).
- Телефония и каскад мессенджеров MAX→WA→TG→SMS — отдельный этап с провайдерами.

### 5.3. Рассылки об акциях — как это будет работать
1. Владелец создаёт кампанию: название → сегмент (готовый или фильтр: источник, тип ТС, дата последнего визита, число визитов, LTV, теги) → превью «попадёт 143 клиента, из них с согласием 118» → шаблон с `{{client.name}}`, `{{promo.code}}` → канал (каскад MAX→WA→TG→SMS, в v1 WhatsApp+Telegram) → время.
2. Планировщик режет Outbox пачками (например, 20 сообщений/мин — лимиты провайдера), пишет Interaction в каждую карточку, обновляет статистику кампании.
3. Клиент отвечает «СТОП» — `doNotDisturb=true`, `consentMarketingAt=null`, запись в журнал. Без согласия сообщение не отправляется никогда (проверка на уровне сервиса, не UI).
4. Отчёт кампании: отправлено/доставлено/прочитано/ответили/забронировали в 14 дней (сопоставление по клиенту) — та же сквозная логика, что в §11.
