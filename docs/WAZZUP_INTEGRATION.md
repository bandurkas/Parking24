# Wazzup24 — провайдер сообщений: что умеет и как подключаем (22.09.2026)

Решение пользователя 22.09: сообщения клиентам идут через Wazzup (wazzup24.ru). Сначала пробный период на нашем аккаунте, затем заказчик покупает свой аккаунт, и мы меняем ключ.

Источник: справка Wazzup, раздел API (`wazzup24.ru/help/api-ru/`), страница тарифов. Проверено чтением документации 22.09.2026; в реальном аккаунте ещё ничего не проверялось.

## 1. Что важно знать до старта

- **Пробный период — 3 дня.** Поэтому сначала пишем и проверяем код на локальной заглушке, и только потом пользователь регистрирует аккаунт. Иначе пробный период уйдёт на разработку.
- **Платят за канал.** Канал — это один аккаунт одного мессенджера. WhatsApp, Telegram и MAX — три отдельных канала и три подписки.
- **Тарифы за канал в месяц:**

| Тариф | Цена | Диалогов в месяц | Писать первым |
|---|---|---|---|
| Start | 1 000 ₽ | 50 | да |
| Inbox | 2 000 ₽ | 500 | **нет** |
| Pro | 4 000 ₽ | 500 | да |
| Max | 6 000 ₽ | без ограничений | да |

  Диалог — переписка с одним контактом в течение месяца. Наш флоу «первым пишет Питстоп», поэтому **Inbox не подходит**: API вернёт ошибку `MESSAGES_NOT_TEXT_FIRST`. Каждая бронь нового клиента — один диалог, так что для парковки на 405 мест реальны Pro или Max. Скидки: 10 % за полгода, 20 % за год.
- **Не выяснено по документации** (проверить в кабинете или у поддержки): какой тариф действует в пробном периоде и можно ли в нём писать первым; что происходит при превышении лимита диалогов; срок жизни ссылки на окно чатов.
- **Канал «WhatsApp» в Wazzup подключается сканированием QR**, как WhatsApp Web. Это неофициальное подключение, риск блокировки номера со стороны WhatsApp остаётся. Официальный вариант — канал WABA: там первое сообщение клиенту возможно только утверждённым шаблоном, наши четыре сообщения пришлось бы зарегистрировать как шаблоны, и есть отдельная плата за переписки.

## 2. API в двух словах

Базовый адрес `https://api.wazzup24.com/v3`, авторизация заголовком `Authorization: Bearer <API-ключ>`. Ключ берётся в кабинете: «Интеграция с CRM» → API → Подключить (для этого в аккаунте уже должен быть добавлен канал). Для самописной CRM одного клиента подходит именно этот простой ключ.

### Отправка — `POST /v3/message`

```json
{ "channelId": "<uuid канала>", "chatType": "whatsapp", "chatId": "79991234567", "text": "…", "crmMessageId": "<id записи Outbox>" }
```

- `chatType`: `whatsapp`, `telegram`, `max` (есть и другие, нам не нужны).
- `chatId` для WhatsApp — номер цифрами с кодом страны, без плюса.
- Для Telegram и MAX, когда идентификатор чата неизвестен, передаётся `phone` — номер цифрами. Так можно написать первым по телефону.
- `crmMessageId` защищает от дублей: повтор с тем же значением в течение 60 секунд отклоняется (`REPEATED_CRM_MESSAGE_ID`). Передаём `Outbox.id`.
- Ответ `201`: `{ "messageId": "<uuid>", "chatId": "…" }`.
- Длина текста: WhatsApp до 10 000 символов, Telegram до 4 096 (справка «Отправка сообщений», перечитана 24.09; в первой редакции этого разбора стояло 1 024), MAX до 4 096. Наши сообщения укладываются, самое длинное (первое) около 600 символов.

Ошибки, которые обрабатываем по-разному:

| Код | Что значит | Что делаем |
|---|---|---|
| `BAD_CONTACT` | номера нет в мессенджере | не повторяем; уведомление администратору «позвоните клиенту» |
| `MESSAGES_NOT_TEXT_FIRST` | тариф не даёт писать первым | не повторяем; уведомление владельцу |
| `MESSAGES_IS_SPAM` | WhatsApp счёл спамом | не повторяем; уведомление владельцу |
| `CHANNEL_NOT_FOUND`, канал не `active` | канал отключён, нужно заново сканировать QR | повтор позже; уведомление администратору |
| `REPEATED_CRM_MESSAGE_ID` | уже отправлено | считаем отправленным |
| сеть, 5xx | временный сбой | повтор с нарастающей паузой |

### Каналы — `GET /v3/channels`

Возвращает `channelId`, `transport` (`whatsapp`, `wapi` — это WABA, `tgapi` — личный Telegram, `telegram` — бот, `max`, `maxbot`), `plainId` (номер), `state`. Рабочее состояние — `active`; остальные (`qridle` — нужен QR, `phoneUnavailable`, `notEnoughMoney`, `blocked`, `unauthorized` и др.) означают, что отправка не пройдёт.

**Идентификаторы каналов не храним в настройках**, а находим по `transport` при работе и кешируем на несколько минут. Тогда при переезде на аккаунт заказчика меняется только ключ.

### Входящие и статусы — вебхуки

Подключение: `PATCH /v3/webhooks` с телом `{ "webhooksUri": "https://…", "subscriptions": { "messagesAndStatuses": true, "channelsUpdates": true } }`. При подключении Wazzup шлёт проверочный `POST` с телом `{ "test": true }` и ждёт ответ `200` в течение 30 секунд.

Приходят три вида событий:
- `messages` — новые сообщения. `isEcho: false` — клиент написал нам. `isEcho: true` — исходящее, отправленное не через API (администратор ответил из окна чатов или с телефона), с полем `authorName`. Поля: `messageId`, `channelId`, `chatType`, `chatId`, `dateTime`, `type`, `text`, `contentUri`, `contact.name`.
- `statuses` — судьба исходящего: `sent`, `delivered`, `read`, `error` (с кодом). Позволяет показывать в карточке «доставлено» и «прочитано».
- `channelsUpdates` — смена состояния канала. Превращаем в уведомление администратору, если канал отвалился.

Механизм авторизации вебхуков по документации неясен (упоминается `crmKey` без описания), политика повторов не описана. Поэтому адрес вебхука содержит наш собственный секрет: `/api/webhooks/wazzup/<секрет>`, а обработчик устойчив к повторам (дедупликация по `messageId`).

### Окно чатов — `POST /v3/iframe`

Wazzup отдаёт ссылку на готовый интерфейс переписки, который встраивается в CRM тегом `<iframe allow="microphone *; clipboard-write *">`.

```json
{ "user": { "id": "<id пользователя CRM>", "name": "Имя" }, "scope": "card",
  "filter": [ { "chatType": "whatsapp", "chatId": "79991234567" } ] }
```

`scope: "global"` — все чаты; `scope: "card"` — переписка с конкретным клиентом (фильтр по его номерам). Перед этим пользователей CRM нужно завести в Wazzup: `POST /v3/users` (массив `{ id, name }`, до 100 за запрос).

**Счётчик неотвеченных:** `GET /v3/unanswered/<id пользователя>` → `{ "counterV2": 7, … }`. Неотвеченным считается сообщение клиента без ответа за последние 7 дней. Для роли «Менеджер» считаются только назначенные ему чаты, для «Руководителя» — все; роль задаётся в кабинете Wazzup.

Это закрывает требование пользователя «администратор видит новое сообщение и может ответить» без разработки собственного мессенджера внутри CRM: Wazzup сам рекомендует эту схему для самописных CRM.

## 3. Как встраиваем в Parking24

Все изменения добавляющие, включаются только при наличии ключа.

- **Переменные окружения (только в серверном `.env`):** `WAZZUP_API_KEY`, `WAZZUP_WEBHOOK_SECRET`, `OUTBOX_ALLOWLIST` (номера через запятую; пока задан, сообщения уходят только на них — предохранитель на время теста).
- **Адаптер** `src/server/messaging/wazzup/` (Ф14, код 24.09): отправка, список каналов с кешем, регистрация вебхука, синхронизация пользователей, ссылка на окно чатов, счётчик. Общий интерфейс адаптера (`src/server/messaging/types.ts`) остаётся, чтобы провайдера можно было заменить.
- **Отправщик** в минутном тике планировщика: берёт из Outbox сообщения, у которых подошло время, под арендой записи (чтобы два тика не отправили одно сообщение дважды), отправляет, пишет результат. Сообщения старше нескольких часов не отправляет, а отменяет с пометкой «устарело»: на stage лежат 7 неотправленных с 08–21.09.
- **Выбор канала:** канал клиента (`Client.messenger`) → активный канал Wazzup с нужным `transport`. Если такого канала нет — любой активный канал, в первую очередь WhatsApp. На сайте в калькуляторе показываем только мессенджеры, для которых есть активный канал (ключ настроек).
- **Схема:** `Outbox` + `lockedUntil`, `providerMessageId`, `deliveredAt`, `readAt`; `Interaction` + `externalId` (уникальный, для дедупликации входящих).
- **Вебхук** `/api/webhooks/wazzup/<секрет>`: входящее сообщение → запись в ленту клиента и его активной брони (поиск по основному и дополнительным телефонам) + уведомление в колокольчике; эхо исходящего → запись в ленту «ответил {имя}»; статусы → отметки в Outbox; состояние канала → уведомление.
- **Окно чатов:** панель «Чат с клиентом» в карточке брони и карточке клиента (`scope: "card"`), страница «Чаты» в меню (`scope: "global"`) с числом неотвеченных. Ссылка запрашивается с сервера при открытии страницы, ключ в браузер не попадает.
- **Настройка аккаунта — кнопкой владельца, не при старте** (решение 24.09 после критики Ф14): «Подключить вебхук и пользователей» в карточке «Сообщения» (`/admin/settings`). Адрес вебхука один на весь аккаунт Wazzup, поэтому регистрируется только на явный публичный https `WAZZUP_WEBHOOK_BASE` — случайный запуск с тем же ключом (машина разработчика) его не перехватит. Пользователи CRM дополнительно синхронизируются сами перед открытием окна чатов. Отметка регистрации привязана к ключу и адресу: после смены ключа карточка пишет «не зарегистрирован для текущего ключа».

## 4. Переезд на аккаунт заказчика

1. Заказчик регистрирует свой аккаунт Wazzup, подключает каналы (сканирует QR своим рабочим номером), оплачивает тариф с правом писать первым (Pro или Max).
2. В кабинете: «Интеграция с CRM» → API → копирует ключ.
3. На сервере меняем `WAZZUP_API_KEY` в `/opt/parking24/.env`, перезапускаем контейнер сайта. Каналы находятся сами (ищутся по транспорту). Затем владелец в `/admin/settings` → «Сообщения» нажимает «Проверить связь» и «Подключить вебхук и пользователей» — без этого ответы клиентов, статусы доставки и смены состояния канала не приходят.
4. В кабинете Wazzup администраторам выставляется роль с доступом ко всем чатам.
5. Убираем `OUTBOX_ALLOWLIST`, возвращаем на сайте боевой номер WhatsApp `79055250660`.

История переписки пробного аккаунта в новый не переносится.

## 5. План теста в пробном периоде

Начинать пробный период только после того, как код проверен на заглушке.

1. Пользователь регистрируется на wazzup24.ru, добавляет канал WhatsApp (QR своим временным номером +62 812 1901 0408), берёт API-ключ.
2. Ключ и секрет кладём только в серверный `.env`, `OUTBOX_ALLOWLIST` = второй номер пользователя.
3. Проверяем: `GET /v3/channels` показывает канал `active`; вебхук зарегистрировался.
4. Заявка на stage с номера из списка → приходит сообщение 1. «Заехал» → сообщение 3. «Выехал» → сообщение 4 (для теста задержку 2 часа сокращаем).
5. Ответ клиента с телефона → запись в ленте брони, колокольчик, счётчик на странице «Чаты»; ответ администратора из окна чатов доходит до телефона.
6. Отметки «доставлено» и «прочитано» появляются в карточке.
7. Проверяем в кабинете то, что не нашлось в документации: тариф пробного периода, поведение при лимите диалогов.
